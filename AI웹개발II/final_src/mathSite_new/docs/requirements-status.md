2026-11-14 구현 완료 후 갱신. 현재 로컬 React/Express 프로젝트 기준이며 GitHub에는 아직 푸시하지 않았다. 이전 비교에서 발견한 누락을 다음과 같이 반영했다. 실행·수정 방법은 [인수인계서](HANDOFF.md), 파일 관계는 [구조 지도](architecture.md)를 본다.

## 현재 정책

홈·소개·로그인·가입은 공개, 공지·질문·내 정보는 로그인 필요, 강좌·영상은 개별 시청 권한이 필요하다. 관리자 카카오 로그인은 DB의 관리자 계정에 카카오를 연결하는 방식이다. 카카오 ID를 코드에 박아 새 관리자로 자동 승격시키지 않는다.

## 평가 라우터 수

회원 관리 이외의 Router는 다음과 같다.

| 모듈     | 주소                              | API 수         |
| -------- | --------------------------------- | -------------- |
| info     | `/api/info`와 하위 settings       | Q&A 8 + 설정 2 |
| courses  | `/api/courses`                    | 6              |
| lectures | `/api/courses/:courseId/lectures` | 8              |
| boards   | `/api/boards`                     | 7              |

기획표의 기존 38개 요청은 유지하며 실제 API에는 `/api` 접두사가 붙는다. 카카오 인증 시작·callback은 `/auth/kakao`도 사용한다. 전체 주소·권한은 [API 목록](API.md)에 있다.

manager는 회원·역할 관리가 중심이어서 평가 제외 대상이 될 수 있다. lectures는 별도 Express Router이지만 강좌 아래에 연결되어 있으므로 **하위 라우터를 별도 평가 대상으로 인정하는지는 담당 교수에게 확인해야 한다.** 이 문서는 인정 여부를 확정하지 않는다.

## 외부 연결·운영에서 남은 일

1. SMTP 계정을 만들고 .env에 연결한 뒤 실제 수신함까지 확인한다.
2. 카카오톡 채널을 만들고 관리자 화면에 실제 주소를 저장한다.
3. 외부에서 함께 재생하려면 한 서버의 원본·HLS 저장소를 사용하도록 배포한다. 현재는 로컬 실행이며 온라인 DB만으로 영상이 공유되지 않는다.
4. 실제 카카오 로그인은 이번 작업에서 계정 재인증을 하지 않았다. 기존 연결 코드·설정은 유지하고 공급자 응답을 대체한 통합 테스트로 검사했다.
5. 보고서 양식·PDF·실제 회의 사진·일지·평가용 시연 자료를 팀에서 준비한다.

실제 외부 계정·호스팅·대면 회의 기록을 만들어 놓은 것처럼 표시하지 않는다.
